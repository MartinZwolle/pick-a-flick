# M11: single-administrator configuration

## Agreed scope

One administrator protects only /admin. Household profiles and movie-night routes
remain accessible without login. Profiles are not authentication accounts.

An interactive local command creates the administrator and resets a lost password.
There is no public setup route, registration, email recovery or role management.
Authenticated administrators can change their password using the current password.
All credential changes invalidate all existing login and administration sessions.

Passwords contain 15–128 characters and are stored as salted Argon2id hashes
(64 MiB, three iterations, one lane), using argon2-cffi. Passwords are never accepted
as command-line arguments or read from environment variables.

## Sessions and forms

A fresh random 256-bit session token is issued after successful authentication.
Only its SHA-256 digest is stored in SQLite; the browser receives an HttpOnly,
SameSite=Strict cookie scoped to /admin. HTTPS cookies are Secure.
Anonymous login forms use separate short-lived sessions and CSRF tokens.
Every administration POST validates its synchronizer token; requests with a
foreign Origin or cross-site Fetch Metadata are also rejected.

Authenticated sessions expire after 30 minutes of inactivity and at 12 hours
absolute age. Login forms expire at 10 minutes. Logout deletes the server session.
An integer credential version prevents a session from surviving password changes.
SQLite BEGIN IMMEDIATE transactions serialize credential, session and settings writes,
including the offline recovery command. Session storage is bounded and old sessions
are removed on issuance. Admin responses disable caching and framing.

Five password checks within 15 minutes impose a 15-minute global cooldown.
This deliberately applies across browsers and worker processes for the one account.
An attacker on the trusted network can cause a temporary admin lockout. Household
use remains available; local password recovery clears the cooldown.
There is no claim that an admin-only login makes the whole application safe to
publish on the internet.

HTTPS is required for admin routes by default. For the agreed LAN deployment,
PICKAFLICK_ADMIN_ALLOW_HTTP=true explicitly permits HTTP. The browser connection
scheme controls Secure; HTTP mode necessarily sends credentials unencrypted.
Forwarded headers are accepted only according to Uvicorn's trusted-proxy configuration.

## Configuration and upgrade

YAML remains mounted read-only and is never rewritten. Existing environment
variables still supply API keys. M11 exposes country, preferred/allowed languages,
subscription/rental providers, earliest movie year and adult-content preference.

settings_overrides stores one JSON object containing only explicitly overridden
fields, plus a revision. Effective settings are the YAML base with these overrides.
The whole candidate configuration is validated before one atomic commit. A stale
form receives 409 rather than overwriting another browser's change. Unchecking a
field removes its override and returns it to the YAML base. Empty provider lists
are legitimate explicit overrides.

Effective settings are read afresh, so new requests and other workers see commits.
The YAML base remains cached until process restart, matching existing behavior.
Existing movie-night candidate lists are not regenerated by a settings change.
API keys, infrastructure options and future AI settings are outside the UI.
Known provider aliases are shown as examples; normalized provider names supported
by the existing availability mapper remain accepted.

Migration 0008 follows 0007 and adds only three tables. Existing profiles, ratings,
catalogue, movie nights and local configuration remain untouched. No override
or default credential is introduced during migration. Without admin setup, ordinary
use continues and admin login displays setup instructions.

Before upgrading, stop writes and make a consistent backup of data, YAML and .env.
The entrypoint's pre-migration copy is not a substitute for that backup.
Rollback: stop the new app, restore the pre-upgrade data and configuration, then
start the previous pinned image. Do not run different versions against the same
SQLite file concurrently. The additive migration also has a tested downgrade to 0007;
downgrading removes admin credentials, sessions and web overrides.

## Verification

Integration tests exercise secure/HTTP cookie behavior, login-token rotation,
CSRF and cross-origin rejection, unauthenticated access, logout, both session
timeouts, global cooldown, password policy/change/reset, live cross-process
settings reads, atomic validation, concurrent form conflicts and YAML reset.
A migration test upgrades a populated 0007 database and checks profile preservation,
then checks downgrade preservation. Existing CI runs pytest, Ruff and the container
migration/health smoke test. PRs do not publish an image.
