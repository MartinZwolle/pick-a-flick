# Pick a Flick v0.10.0

M11 adds a single administrator for web configuration. Movie nights and viewer
profiles remain accessible without individual accounts.

## New

- Admin login with Argon2id password storage, server-side sessions, CSRF protection
  and a persistent password-attempt cooldown.
- Sessions expire after 30 minutes idle or 12 hours total. Logout, password changes
  and local password recovery revoke sessions.
- Web configuration for country, languages, streaming subscriptions, rental
  providers, earliest film year and adult content.
- Per-field SQLite overrides preserve the read-only YAML base and can be removed
  to return to YAML. Stale browser forms cannot overwrite newer changes.
- HTTPS by default, with an explicit HTTP exception for a trusted home network.

## Upgrade from v0.9.0

1. Stop application writes and make a consistent backup of the persistent data
   directory, config.yaml and .env. Retain the previous pinned image version.
2. Once image 0.10.0 has been published, select it in your registry deployment
   with PICKAFLICK_VERSION=0.10.0, then pull and recreate the application container.
   Local-build deployments must rebuild from the v0.10.0 source instead.
3. Startup migration 0008 adds admin, session and settings tables. Existing
   profiles, ratings and movie nights are retained; no default password is created.
4. For direct HTTP on a trusted home network, set
   PICKAFLICK_ADMIN_ALLOW_HTTP=true in .env before recreating the container.
   HTTP sends credentials without transport encryption.
5. Create the admin password interactively with your selected Compose file:

   docker compose -f compose.ghcr.yaml exec pick-a-flick python -m app.admin.cli set-password

   For a local-build deployment omit -f compose.ghcr.yaml. Use 15–128 characters.
6. Open /admin/login, then verify the settings and normal movie-night flow.

A forgotten password can be reset locally using reset-password in place of
set-password. API keys remain in environment variables.

## Limits and rollback

Admin login protects /admin only. Public household routes and /metrics still
require an external access-control layer if exposed outside a trusted network.
Preferred/allowed language values are stored but are not yet applied as movie
filters. Existing candidate lists are not regenerated when settings change.

For rollback, stop the new application, restore the complete pre-upgrade backup,
and start the previous pinned version. Changing only the image does not undo
database or web-setting changes. Never run both versions against the same database.

See the README and docs/M11.md for setup, proxy and recovery details.

## Validation

The M11 implementation passed 28 tests, Ruff, both Compose validations, the Docker
build and startup migration/HTTP health checks in GitHub Actions. Release preparation
runs the same checks again. Publishing and homelab upgrade remain separate actions.
