# Pick a Flick v0.10.1

## Fixed

Admin login on explicitly enabled HTTP deployments could fail with
"Dit formulier komt niet van deze website." Browsers sent Origin: null because
admin pages used Referrer-Policy: no-referrer. The response policy is now
same-origin, allowing same-origin forms to retain their Origin.

CSRF tokens, rejection of null/foreign origins, SameSite session cookies and the
default HTTPS requirement remain in place. The fix was merged in
[PR #7](https://github.com/MartinZwolle/pick-a-flick/pull/7).

## Upgrade

This patch adds no database migration and requires no new configuration.
Existing admin passwords, web settings and household data are retained.

For local builds, after this tag is published:

```bash
git fetch origin --tags
git switch --detach v0.10.1
docker compose up -d --build
docker compose ps
```

For registry deployments, after image 0.10.1 is published, set
PICKAFLICK_VERSION=0.10.1 in the existing .env, then:

```bash
docker compose -f compose.ghcr.yaml pull
docker compose -f compose.ghcr.yaml up -d
docker compose -f compose.ghcr.yaml ps
```

Keep the existing HTTP opt-in if using a trusted LAN deployment. Once healthy,
close old login tabs, open a fresh /admin/login page and sign in again. There is
no need to recreate or reset the admin password.

For installations still on v0.9.0, follow the backup and initial admin setup in
[the v0.10.0 upgrade notes](v0.10.0.md) and install v0.10.1 instead.

## Verification

The fix passed 33 tests, Ruff, Compose validation, container build and startup
migration/health checks. A real Chromium test reproduces the old policy's failure,
then verifies HTTP login, session redirects, settings save and logout with the fix.
The user also confirmed successful login on their local homelab build.

Release preparation reruns CI, the Chromium regression and container checks.
Tag/image publication and installation upgrades remain separate steps.
