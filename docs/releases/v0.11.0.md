# Pick a Flick v0.11.0

## Added

M12 adds an optional AI film expert as a source for the existing solo/group Movie
Night game. Natural-language wishes become up to ten unique, TMDb-verified films.
The game starts directly with the available cards; zero results show a clear message.
Configured streaming subscriptions/rental services and region are hard filters;
taste, seen history and vetoes are soft signals in this source. Creative matches
have short labelled explanations. A film reel rotates playful loading texts.

Providers: DeepSeek, Ollama, OpenAI, Anthropic and OpenAI-compatible endpoints.
M11 administration now manages provider, model, endpoint and AI enablement.
Keys stay in the server environment. DeepSeek uses a fixed HTTPS endpoint, JSON
mode, max_tokens=4096 and thinking disabled. See [M12](../M12.md) for settings,
privacy, timeouts and limits. AI remains disabled by default.

## Publication

This commit prepares the release. Merging alone does not publish a container.
After the release-preparation PR is merged and CI is green on the resulting main
commit, publish a new, unused stable tag v0.11.0 pointing at that commit.
The Container workflow validates and publishes:

    ghcr.io/martinzwolle/pick-a-flick:0.11.0

Wait for the publish job to succeed before deploying the registry image.
Do not reuse or move an existing version tag. The workflow publishes linux/amd64;
there is no latest alias. Existing release tags and images remain unchanged.

## Upgrade on your homelab

Run commands in the existing Pick a Flick directory. Use the same Compose variant
as your current installation. Keep config.yaml, .env and data; never overwrite
them with the example files during an upgrade.

1. Stop writes and back up the persistent database and configuration. For a registry
   installation:

```bash
docker compose -f compose.ghcr.yaml stop pick-a-flick
umask 077
backup_dir="../pick-a-flick-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup_dir"
cp -a data config.yaml .env "$backup_dir/"
```

For a source-build installation, use `docker compose stop pick-a-flick` instead.
If your deployment uses different bind-mount paths, back up those actual paths.
Keep this backup private: it includes API keys and personal data.

2. Update the checkout after v0.11.0 is published. Preserve any local changes:

```bash
git fetch origin --tags
git switch --detach v0.11.0
```

3. Open the existing .env in your editor and set PICKAFLICK_AI_API_KEY to your
   DeepSeek API key. For a registry installation also set PICKAFLICK_VERSION=0.11.0.
   Preserve TMDB_API_KEY and any existing HTTP admin opt-in. Do not paste secrets
   into chat or shell arguments.

4. For the registry installation:

```bash
docker compose -f compose.ghcr.yaml pull
docker compose -f compose.ghcr.yaml up -d --force-recreate pick-a-flick
docker compose -f compose.ghcr.yaml ps
curl --fail http://localhost:8089/health
```

For a source build, use this alternative:

```bash
docker compose up -d --build --force-recreate pick-a-flick
docker compose ps
curl --fail http://localhost:8089/health
```

5. In Beheer, check 'Via web beheren' for AI enabled, provider and model. Set
   active to Ja, provider to deepseek and model to deepseek-flash; save. Leave the
   endpoint blank. An existing gpt-4.1-mini YAML value is not automatically replaced.
   Use a model ID supported by your DeepSeek account if model availability changes.
6. Open Filmavond, select one or more viewers, choose AI-filmkenner and enter a
   film wish. Verify that cards appear and show your services. This first real
   request requires valid API credit; it is separate from mocked CI tests.

No new database migration is added beyond M11's existing migration 0008. Profiles,
admin password, saved settings and old film evenings are retained. There is no need
to reset the admin password. AI failures do not remove ordinary discovery modes.

## Rollback

If startup fails, inspect logs with your existing Compose variant. Restore the
previous pinned image/configuration and, if necessary, the consistent backup while
writes are stopped. Never run both versions against the same database. Rolling
back an image alone does not restore settings changed after the backup.

## Verification and limitations

M12 passed 71 tests, Ruff, Chromium, Compose validation, container build and migration/
HTTP-health checks. Release preparation reruns CI and container checks.
DeepSeek contracts and errors are tested with simulated HTTP responses; no real
cloud API request or homelab deployment was performed during release preparation.
TMDb data may lag (cache up to 24 hours), and strict title/year verification or the
bounded suggestion pool may yield fewer matches. AI explanations can be inaccurate.
