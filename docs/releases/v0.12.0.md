# Pick a Flick v0.12.0

## Added

M13 adds scheduling after a won solo/group movie game: required date and manually
chosen start time, rescheduling and confirmed cancellation. Everyone with access
to the game can manage its appointment. The result displays the appointment and
**Filmavonden** lists upcoming evenings and history, updated automatically at start.

Optional Telegram integration sends planning/change/cancellation messages, a reminder
on the film day at 10:00, one hour before the start and a rating request the following
morning at 10:00 linked to existing feedback. Settings live in the protected admin
screen: one encrypted bot-token, one chat-ID, public website address, test button
and IANA timezone (default Europe/Amsterdam). UTC storage and local calendar rules
respect DST. Invalid and ambiguous clock-change times are rejected.

The SQLite outbox persists across restarts. A background worker starts with FastAPI;
no additional container or scheduler is required. Revisions and unique keys prevent
duplicate processing and replace stale reminders. Telegram is off by default and
planning works without an encryption key or Telegram connection.

## Publication

After the release PR is merged and checks are green, tag the resulting main commit
with the new, unused stable tag `v0.12.0`. The Container workflow validates and publishes:

```text
ghcr.io/martinzwolle/pick-a-flick:0.12.0
```

Wait for successful publication before pulling. The image targets linux/amd64.
Existing release tags/images remain unchanged; no `latest` alias is published.

## Upgrade from v0.11.0

Run in the existing installation directory. Keep the same Compose variant and
persistent paths. Do not replace config.yaml or .env with the examples.

For a registry installation, stop writes and make a private consistent backup:

```bash
docker compose -f compose.ghcr.yaml stop pick-a-flick
umask 077
backup_dir="../pick-a-flick-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup_dir"
cp -a data config.yaml .env "$backup_dir/"
git fetch origin --tags
git switch --detach v0.12.0
```

Preserve local changes if Git reports a conflict. Adapt backup paths if your actual
bind mounts differ. Edit the existing `.env` and set `PICKAFLICK_VERSION=0.12.0`,
preserving TMDb/AI keys and any HTTP admin opt-in. Then:

```bash
docker compose -f compose.ghcr.yaml pull
docker compose -f compose.ghcr.yaml up -d --force-recreate pick-a-flick
docker compose -f compose.ghcr.yaml ps
curl --fail http://localhost:8089/health
```

For a source build, use `docker compose stop pick-a-flick` for the stop, take the
same backup, fetch/check out the tag, then run:

```bash
docker compose up -d --build --force-recreate pick-a-flick
docker compose ps
curl --fail http://localhost:8089/health
```

Startup migration 0009 adds three tables without removing existing profiles,
spells, ratings, admin sessions/password or web settings. No password reset is needed.

## Telegram setup after upgrading

If `PICKAFLICK_SECRET_KEY` is not already configured, generate it into the existing
server `.env` without displaying it. Do this once, using the new running image:

```bash
umask 077
docker compose -f compose.ghcr.yaml exec -T pick-a-flick python -c \
  'from cryptography.fernet import Fernet; print("PICKAFLICK_SECRET_KEY=" + Fernet.generate_key().decode())' >> .env
docker compose -f compose.ghcr.yaml up -d --force-recreate pick-a-flick
```

For source builds omit `-f compose.ghcr.yaml`. Do not replace an existing key: losing
it requires entering the token again. Keep the key outside the database and protect
its backup. Add the bot to the target group. In Beheer enter its token, numeric
chat-ID including the minus sign, website address and timezone. Enable Telegram,
save, then send a test message. Enter the bot-token only in that password field.
Check Filmavonden and a won game's result; plan an evening and verify the group
receives its planning message. This operational test requires your real Telegram setup.

## Rollback and limitations

If startup fails, inspect logs, stop the new app and restore the consistent backup
with the previous pinned image. An image rollback alone does not undo migration 0009.
Never run old and new versions against the same database concurrently.

Telegram has no idempotency key. Each outbox item gets at most one delivery attempt;
an uncertain response or crash after claiming can lose a message. Automatic retries
are avoided to prevent duplicates, including for explicit Telegram failures.
Past reminders are skipped, with a 60-second polling tolerance; direct change messages
expire after 24 hours. Existing appointments keep their instant when timezone changes.
See [M13](../M13.md) for delivery states and operational details.
